# Changelog

All notable changes to **MolBioCraft** will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-11-09

### Added
- **Bioinformatics Plugins on every menu**: the thirteen built-in plugins (Eukaryotic and Microbial Gene Predictors, CRISPR Repeat Array Finder, Microsatellite & Tandem Repeats, Haplotype & Allele Partitioner, Taxonomic Sequence Classifier, Species Delimitation, Protein Domains & Epitopes, Transmembrane & Signal Topology, Adapter & Quality Read Trimmer, Whole-Genome Synteny Blocks, HPC Phylogeny Job Builder, External CLI Suite) are under Tools › Bioinformatics Plugins in the native macOS menu bar and the in-window menu bar, under the toolbar's Workflows ▾ menu, and in the search bar. Before, they were reachable only from the in-window menu, which the macOS desktop app hides. Each plugin's method is cited in PROVENANCE.md.
- **Mol* 3D structure viewer**: PDB and mmCIF structures render in Mol* (MIT, credited in NOTICE) with representation presets, styles, colour schemes, a sequence panel, ligands, superposed Model B and PNG export.
- **Preferences that take effect**: Files & Tabs › default folder for opening and saving files and default Author for new files, Export › default format for DNA, RNA, protein and alignment exports, and the other General, DNA, RNA, Protein, Gel, Trace, Enzyme, Primer and Keyboard settings are now saved, applied at once, exported to and imported from `.mbcprefs.json`, and restored by Reset All Preferences.
- **Styled macOS disk image**: the `.dmg` opens on a light-blue grid welcome window with the app icon, an Applications shortcut and an arrow between them, and its licence agreement is set in Google Sans.
- **Align Structures…** is on the menus: Tools › Alignment and the toolbar's Align dropdown, and the native Alignment menu on the desktop. It opens the structure alignment window (align two chains by structure, TM-align-style, or by sequence) and is disabled until the session holds a structure document; in the in-window menus the greyed item's hint gives the reason. It can be given a keyboard shortcut or toolbar button, and has a help topic.
- **3D Structure tab, viewer annotations**: for an mmCIF structure the viewer shows the ligands bound to the chains it draws, colours by the helices and strands the file declares ("SS from file"), and highlights the residues of the selection made in the sequence view (clicking a feature selects its range). For legacy PDB text the tab says these are read from mmCIF.
- **3D Structure tab, Ramachandran plot**: the open chain's backbone torsions are plotted under the viewer, naming the plotted model for an entry of several models ("model 1 of 2"). mmCIF only; for legacy PDB text the tab says why there is no plot.
- **The nightly and release reference check re-checks the Ramachandran derivation**: `scripts/check_reference_suite.mjs` runs `derive_ramachandran_maps.py --check` and fails when a cell of the six region maps in `crates/molbiocraft-protein/src/backbone.rs`, or one of their doc comments, no longer matches what the Top8000 grids derive, as NOTICE and PROVENANCE.md describe. It fetches the six grids from their pinned commit and checks their SHA-256, so it needs network access to raw.githubusercontent.com; a failed download fails the check. `node scripts/check_reference_suite.mjs --only ramachandran` runs that step alone, and `MOLBIOCRAFT_REFERENCE_RAMA_GRIDS=DIR` keeps the grids in DIR, so a later run downloads only the ones missing. The other `MOLBIOCRAFT_REFERENCE_*` variables replace the commands the check runs (Vitest, cargo, Python and the derivation script) and the maps it checks. The check prints each one that is set, and with none set it runs as before.
- Engine warnings appear in a shared Caution Amber note beside the result in the alignment studio and the MS digest, and a Multiple Alignment result keeps its warnings in its Notes. (US-01M6P25H)
- Export > Alignment Image > SVG, PNG or PDF saves the whole active alignment as a figure (blocks of 60 columns with a ruler, consensus row, each row's name and percent identity, the studio's default colours); an alignment too large for a canvas is refused with the limit named. (US-01M6S8C5)
- drag handles on the alignment studio's side panel and its sequence name and identity column (also moved with the arrow keys); both widths are kept across views and restarts; nothing changes until a handle is dragged. (US-01M6S7QS)
- **Installers for every platform, each built on its own system**: each release now offers `MolBioCraft-<version>-macOS-universal.dmg` (one app for Apple Silicon and Intel Macs, macOS 11 or later), `MolBioCraft-<version>-Windows-x64.msi`, `MolBioCraft-<version>-Windows-x64-Portable.exe` (runs without installing; needs the WebView2 runtime that Windows 10 and 11 include) and `MolBioCraft-<version>-Linux-x86_64.deb` (`sudo apt install ./MolBioCraft-<version>-Linux-x86_64.deb`), with `SHA256SUMS.txt`, `NOTICE.txt` and `PROVENANCE.md` beside them. The Tauri bundler builds each on a macOS, Windows or Ubuntu 22.04 runner, and each is checked to be the architecture it is named for before it is uploaded. Before, the release built only the macOS disk image, and its Windows and Linux files could not hold a working app. The builds are unsigned (the Mac app is ad-hoc signed), and README.md gives the first-launch steps past Gatekeeper and SmartScreen. Only a pushed `v*` tag publishes a release; running the workflow by hand uploads the same files as workflow artifacts. `npm run package:installers` now builds only the macOS universal `.app` and `.dmg`, with the Tauri bundler. (US-01M6TK7V)
- **One shared inspector in every task window**: Vectors, Cloning, Primers, Alignment (Pairwise and Dotplot), Tree, Chromatogram, Genomics, History/Protein and the Text tab now keep their settings in the same right-hand inspector as the Sequence view, with the same header button, Cmd/Ctrl+Alt+I, View › Panels › Inspector, resize handle and width. A window with nothing to set shows no button, and only one inspector shows at a time. Drawn on its own, outside the workbench, each studio keeps its settings where they were. (US-01M6TAW8, US-01M6TAT0, US-01M6TA1H, US-01M6TANN, US-01M6TA6T, US-01M6TAKD, US-01M6TAA4, US-01M6TAAR, US-01M6TA87, US-01M6TAZE, US-01M6TAKR, US-01M6TAZ7)
- The Flatfile tab's toolbar names the chosen record format beside its label, and its format buttons report their pressed state to assistive tools. (US-01M6TAZ7)
- A shared App test harness drives the real App, with its stores, menus and inspector, so each inspector change is proved in the running app. (US-01M6TB6G)

### Fixed
- **Minimum Evolution and Maximum Parsimony no longer save a tree on a made-up distance**: when a pair's distance is undefined under the chosen model (no shared sites, or too divergent), Build Tree refuses with the engine's sentence naming the pair, as Neighbor-Joining and UPGMA do. Before, the pair silently got twice the largest real distance and the tree was saved under the model's name. A bootstrap or jackknife replicate that meets such a pair is now counted in the tree's warnings. (BG-01M6SB24)
- **VCF annotation reads every NCBI genetic code**: coding consequences now use the same NCBI tables as translation. Before, codes 3, 5, 9, 13 and others were read as the Standard code with no warning, so, for example, TGG>TGA under code 5 was called `stop_gained` instead of synonymous. (BG-01M6SC3D)
- **Startup tagline**: the splash shown while the app loads breaks the tagline in the same place as the app's own splash, so it no longer reflows at the handoff. (BG-01M6ZGN1)
- **Mol* settings panels open**: the Screenshot / State and Settings / Controls Info panels opened with no height once the toolbar moved to the bottom, and the Toggle Controls Panel button had no panel to show; both now open. Full-window view no longer gets stuck because the viewer's container trapped its fixed position.
- **Construct cockpit ORF badge** now reads the whole selection: its codon count, internal stops and last codon were taken from the first 4,000 bp only. A cut peptide preview says so in residues, a terminal stop codon not counted, for example "(first 12 aa of 3,332)" (or "(first 18 aa of 40)" for a protein), and the In-Frame badge's "(N aa)" counts residues the same way. The status bar and the selection quickbar read "Tm n/a" for a selection of 14 bases or more with fewer than 14 A/C/G/T bases, instead of a negative or 0 °C Tm.
- **Large sequences, map ORF floor and readouts**: the circular map says its ORF arcs show only ORFs of 120 aa or more (or the slider's minimum) in the first 60,000 bp, the split pane works out its cut-site scan from the same rule as the main view, the construct cockpit's GC, skew and duplex Tm cover the whole span instead of its first 4,000 bp, and the selection quickbar uses the Wallace Tm rule only below 14 bases, as the status bar does, with N and other IUPAC codes left out of GC and Tm in both.
- **Large sequences' split pane, ORF arcs and selection readouts**: over 150,000 bp the split pane's linear view says where its cut sites stop, as the main view does, and the circular map says "ORFs: first 60,000 bp" when its ORF arcs come from that range only. The status bar's selection readout and the linear view's selection bar give the whole selection's GC and Tm instead of the first 12,000 bp's. RNA Statistics read "A / C / G / U" and "%GC / %AU" with U counted once, and the ORF list follows a change of topology.
- **Mixed-peak counts**: the chromatogram studio states each read's real number of mixed IUPAC peaks in the cockpit, the parameters tab, Trace Statistics and the trimming section ("19 of 74 in the trimmed region", "311 over the whole read") instead of the 32 its peak list stops at, and the peak table says when it lists only the first 32.
- **Large sequences, ORFs, cut sites and statistics**: on sequences over 150,000 bp the ORF counts name the range and minimum scanned, and the linear map says where its cut sites stop; Statistics are counted on the whole sequence instead of scaled up from a 12 kb sample, and a Dam or Dcm count that fills its 4,096-site list reads "at least 4,096".
- **Large sequences' restriction sites**: a sequence over 150 kb no longer reports the sites in its first 60,000 bp as the whole molecule's. The circular map's note names the range scanned at every map size, zoom and pan ("9,570 more labels not shown, first 60,000 bp scanned", or "Cut sites: first 60,000 bp only"), the Restriction Analysis header and its "Cutting once in the first 60,000 bp" list name it too, and neither the map (no bold blue), its plate ("cut once", not "unique") nor the construct cockpit marks a unique cutter from it; the plate keeps its annotation count. A sequence over 100 kb, scanned with the 28 core enzymes, says so on the map's note, in Restriction Analysis and in the Hybrid tools Enzymes view ("Cutting once among 28 core enzymes").
- **Chromatogram trimming**: the studio shows no high-quality region, trim coordinates, mean Phred or Save for a trace whose qualities do not support one, and says why: "No high-quality region" when no base beats the cutoff, "No quality values in this file" when it has none (said that one way on every surface), or "29 quality values for 30 base calls" when the file's quality values and base calls differ in number. Beside no region the mixed-peak count reads "over the whole read", and every HQ-window surface names its fixed P(err) cutoff 0.05. The engine's own trim reply is unchanged (BG-01M6RPCA). A read the trim cannot score (no quality values, or quality values that do not match its calls in number) says "Not trimmed" and why, instead of being reported as trimmed to 0 bp and too short to use.
- **3D Structure badge** now says where the coordinates come from, as the structure file states it: "Measured Cα coordinates (X-ray)", "(NMR)", "(neutron)", "(fiber diffraction)", "(powder diffraction)", "(electron crystallography)" or "(solution scattering)"; for electron microscopy "(cryo-EM)" only when the mmCIF file says the specimen was vitrified, "(negative-stain EM)" only when it states a negative stain for a specimen it does not say was vitrified or unstained, and "(electron microscopy)" otherwise, as for every PDB file; any other method as the file states it; "Predicted model (AlphaFold, pLDDT in B-factor)" for an AlphaFold model, "Predicted model" for another model (a ModelCIF file, or a method that begins THEORETICAL MODEL or PREDICTED MODEL); and "Cα coordinates (source not stated)" when the file says nothing, even if its title mentions AlphaFold. A predicted model is no longer called measured, and a protein with no coordinates shows no badge.
- **Multi-record EMBL and GenBank files**: a first record with no sequence (a CON or CONTIG record) now ends at its `//` line, so it keeps its own name, description, length and features instead of taking the next record's; test-data's Human_contigs.embl reads as AJ229040, "Homo sapiens 959 kb contig between AML1 and CBR1 on chromosome 21q22", as Biopython reads it.
- **Circular map identity plate** now counts every unique site the Restriction Analysis list holds (35 on pUC19) instead of the 32 at most the map can label, and with all cutters shown it counts every cut site (429 on pUC19) instead of 32.
- **GenBank and EMBL import** keep the continuation lines of a wrapped unquoted qualifier (/transl_except, /anticodon, as NCBI and Biopython write them), which were read into the feature's location, so a long /transl_except no longer imports cut short. ### Fixed — phylogenetics and molecular evolution (`molbiocraft-phylo`)
- **Distances**: no clamps; saturated or non-overlapping pairs are reported as not computable ("n/c") instead of being forced to a number; delta-method standard errors; within/between/net group distances come only from real group labels (a sequence description that reads `Group: …`, or an imported `Group` metadata field), not from splitting the taxon list in half. ### Fixed — engine RPC contract (`molbiocraft-wasm`)
- **Semi-global alignment was running as a global alignment.** rust-bio's `semiglobal` leaves only the *second* sequence's ends unpenalised, so a short query against a long target was charged for both overhangs: `ACGTACGT` vs `TTTTACGTACGTTTTT` came back split as `----ACGTACG----T` with score −2. It is now a free-end-gap alignment on both sequences (`----ACGTACGT----`, score 16), which is what MolBioCraft's "free end gaps" label means: at each end, the overhanging residues of one sequence are left unaligned at no cost, the way EMBOSS `needle` aligns by default, where end gaps carry no penalty unless end-gap penalties are switched on. `align_pairwise` also accepts `mode` (`global`/`local`/`semiglobal`); it previously understood only a boolean `local`, so a `semiglobal` request was silently answered with a global alignment.
- **A contract test now covers all 156 RPCs the app sends**: for each one it checks that the dispatcher actually reads every key of the payload. A key the TypeScript side sends under a name the Rust side never looks at is silently replaced by a default — the failure mode behind the earlier `bins`/`overviewBins` and `bothStrands`/`searchBothStrands` bugs — and is now caught by `cargo test`.

### Fixed — file formats (validated against real files in `resources/`)
- **SCF chromatograms** (Staden, many sequencers and sequence editors) are now decoded (v2 and v3, delta-encoded samples, peaks, per-base quality, run comments). Previously `.scf` files were scanned for the longest A/C/G/T run, imported as circular plasmids without traces, and short runs were replaced by a hard-coded GFP fragment with a synthetic trace. The COI test reads decode bit-for-bit identical to their ABIF traces and match the FASTQ qualities.
- **Proprietary plasmid-map `.dna` / `.prot` / `.rna`** files were read from their packet structure: DNA/RNA/protein sequence, topology and strandedness, all features (multi-segment and origin-spanning ranges, strand, colours, qualifiers), primers and notes. Previously features were lost and every file was forced circular. (This reader has since been removed; see Removed under [Unreleased].)
- **ABIF (`.ab1` / `.abi`)**: no more invented Phred 40 scores, synthetic Gaussian traces or evenly spaced peaks when a file lacks them (raw DATA 1-4 are used when processed traces are absent); instrument, model, sample and dye-set tags are kept. Unrecognised binaries import nothing instead of a placeholder sequence.
- **Chromatogram viewer**: trace windows and base letters are placed by recorded peak positions (the old fixed 10 samples/base drifted away from the base calls); missing qualities are shown as missing, Mott trimming does not trim on absent qualities, and the signal-to-noise fallback of 28.5 was removed.
- **GenBank / EMBL**: `join(...)`, `order(...)` and `complement(join(...))` locations, wrapped location lines and multi-line qualifiers are read; exports write joins, all qualifiers, a single source feature and a standard 79-column LOCUS line. A record without ORIGIN is no longer filled with the letters of the flatfile text; summary records export their declared length.
- **GFF3**: names come from `Name`/`gene`/`product`/`ID`; unstranded features stay unstranded; multi-line features with one ID become segmented features; CDS phase is computed per exon on export. **BED**: 0-based starts converted, name/strand kept, BED12 blocks become segments.
- **Proprietary alignment `.meg`** import (sequential, interleaved and multi-gene data; identical-site dots expanded; group labels separated); distance-matrix files are reported rather than imported. All 44 sample `.meg` files parsed. (This reader has since been removed; see Removed under [Unreleased].)
- **PDB**: each protein chain becomes its own document (chains were concatenated into one invented sequence); imported structures now store `PDBText` so the structure tab and source download work.
- **GFF/BED overlays** skip features outside the sequence and report them instead of clamping them onto its ends.

### Fixed — sample library scientific accuracy (validated against `resources/`)
